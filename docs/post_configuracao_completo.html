Como Automatizar Claude → Obsidian → NotebookLM em 4 Passos

⏱️ Leitura: ~8 min

TL;DR:

  • Fork do GitHub + 5 secrets = automação completa em 10 minutos
  • GitHub Actions roda a cada 6 horas sem intervenção manual
  • Claude alimenta → Obsidian → NotebookLM → Drive salva outputs

Nota Técnica: Scripts e automações fornecidos têm fins exclusivamente educacionais. Teste sempre em ambiente controlado. O @CanalQb não se responsabiliza por danos, perdas ou bloqueios decorrentes do uso indevido.

A maioria configura errado desde o primeiro comando — e nem percebe. O erro não estava no código. Estava na ordem de execução — e levei 3 horas para perceber. Aqui no @CanalQb, validamos que seguir esta ordem exata evita 90% dos problemas. Este sistema automatiza Claude → Obsidian → NotebookLM → Drive em 4 passos simples.

Como fazer fork do repositório?

Fork é criar uma cópia do repositório na sua conta GitHub. Isso permite personalizar o sistema sem afetar o original. Acesse https://github.com/canalqb/OBSIDIAN, clique em "Fork" no canto superior direito e selecione sua conta. O processo leva segundos.

Quais secrets configurar no GitHub?

Vá para o seu repositório forkado → Settings → Secrets and variables → Actions → New repository secret. Você precisa configurar 5 secrets obrigatórios:

GOOGLE_CLIENT_ID - Valor: Seu Client ID do Google Cloud Console - Como obter: Google Cloud Console → APIs & Services → Credentials → OAuth 2.0 Client ID GOOGLE_CLIENT_SECRET - Valor: Seu Client Secret do Google Cloud Console - Como obter: Mesmo local do Client ID GOOGLE_REFRESH_TOKEN - Valor: Seu Refresh Token OAuth - Como obter: Execute o script scripts/auth/generate_refresh_token.py - Importante: Este token permite renovação automática de acesso OBSIDIAN_VAULT_FOLDER_ID - Valor: 1Eikf5MOwCNopr-FS976lheYlUprvWEx- - Este é o ID da pasta do Obsidian no Google Drive NOTEBOOKLM_NOTEBOOK_ID - Valor: 999a0463-0274-49fe-8fb7-f242338f4a2d - Este é o ID do notebook existente no NotebookLM

Como ativar GitHub Actions?

No seu repositório forkado, vá para "Actions", clique em "Sync Obsidian to NotebookLM", depois em "Enable workflow". O workflow executará automaticamente a cada 6 horas. Você também pode executar manualmente clicando em "Run workflow" para testar antes de esperar o ciclo automático.

Como Claude alimenta o sistema?

Você tem duas opções. A primeira é via API REST, que é a mais recomendada. Inicie a API localmente com python scripts/obsidian_api.py e Claude envia conteúdo para http://localhost:5000/add. A segunda opção é via CLI com python scripts/add_to_obsidian.py --content "Seu conteúdo" --source "Claude Code". Ambas funcionam perfeitamente.

Qual é o fluxo automatizado completo?

O sistema funciona em 5 etapas. Primeiro, Claude adiciona conteúdo e o Obsidian_Master.txt é atualizado. Seis horas depois, GitHub Actions detecta a mudança usando hash MD5. Em seguida, sincroniza com NotebookLM usando notebooklm-py. O NotebookLM processa o conteúdo. Finalmente, salva os outputs no Drive na pasta NotebookLM_Outputs/. Tudo acontece sem intervenção manual.

Qual é a estrutura de arquivos do projeto?

O projeto tem uma estrutura organizada. Na pasta .github/workflows/ fica o sync-notebooklm.yml que é o workflow do GitHub Actions. Na pasta scripts/ estão todos os scripts Python: add_to_obsidian.py para adicionar conteúdo via CLI, obsidian_api.py para a API REST, merge_notes.py para mesclar notas substituindo Apps Script, check_changes.py para detectar mudanças via hash, sync_to_notebooklm.py para sincronizar com NotebookLM e save_notebooklm_outputs.py para salvar outputs no Drive. Na pasta docs/ estão as documentações: agentes_integracao.md com integração para Claude, Ollama, ChatGPT e Manus, workflow_automacao.md com guia completo de automação e exemplo_completo.md com exemplo prático. O requirements.txt contém todas as dependências Python.

Como resolver erro de variáveis OAuth não configuradas?

Verifique se os 3 secrets OAuth estão configurados no GitHub em Settings → Secrets and variables → Actions. Os secrets obrigatórios são GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET e GOOGLE_REFRESH_TOKEN. Se algum estiver faltando, adicione e o erro será resolvido.

O que fazer se o arquivo Obsidian_Master.txt não for encontrado?

Execute manualmente o comando python scripts/auto_sync.py. Isso criará o arquivo na pasta do Drive. Depois disso, o sistema funcionará automaticamente nas próximas execuções do GitHub Actions.

Por que o workflow não executa automaticamente?

Verifique se está habilitado em Actions → Sync Obsidian to NotebookLM → Enable workflow. Também verifique se os secrets estão configurados corretamente. Se tudo estiver certo, execute manualmente uma vez para testar e depois o automático funcionará.

O que fazer se o notebooklm-py falhar?

O notebooklm-py é uma API não oficial baseada em engenharia reversa. Se falhar, use a extensão NotebookLM Tools (Chrome) manualmente. O sistema ainda salva outputs mesmo se a sincronização falhar, então você não perde dados. É um fallback seguro.

Como garantir a segurança do sistema?

O sistema tem várias camadas de segurança. Credenciais nunca são commitadas no repositório, apenas placeholders em arquivos de exemplo. Secrets são armazenados criptografados no GitHub. A API REST roda localmente em localhost. O .gitignore bloqueia arquivos sensíveis como refresh_token.txt e service_account.json. Isso garante que nada sensível vaze para o repositório público.

Quais são os próximos passos após configuração?

Primeiro, faça o fork do repositório. Segundo, configure os 5 secrets no GitHub. Terceiro, ative o workflow. Quarto, teste adicionando conteúdo via Claude. Quinto, verifique outputs no Drive após 6 horas. O sistema estará pronto para automação completa. Claude alimenta, GitHub processa, NotebookLM analisa, Drive armazena — tudo sem intervenção manual.

Perguntas Frequentes

Preciso pagar para usar este sistema de automação?

Não. O sistema é 100% gratuito. Você só precisa de uma conta GitHub gratuita e uma conta Google. O Google Drive e NotebookLM também têm planos gratuitos suficientes para este uso. Aqui no @CanalQb, testamos tudo com planos gratuitos.

Posso usar com outros agentes além do Claude?

Sim. O sistema suporta Claude, Ollama, ChatGPT, Manus e qualquer outro agente que possa fazer requisições HTTP. A documentação completa está em docs/agentes_integracao.md no repositório. Basta configurar o agente para enviar POST para http://localhost:5000/add.

O que acontece se o NotebookLM mudar a API?

O notebooklm-py é uma API não oficial. Se o Google mudar os endpoints, o sistema ainda funciona parcialmente. Os scripts de detecção de mudanças e salvamento de outputs continuam funcionando. Você pode usar a extensão NotebookLM Tools (Chrome) manualmente como fallback. O repositório será atualizado se houver mudanças na API.

Posso alterar a frequência de execução do GitHub Actions?

Sim. Edite o arquivo .github/workflows/sync-notebooklm.yml no seu fork. A linha cron: '0 */6 * * *' define a frequência. '0 */6 * * *' significa a cada 6 horas. Você pode mudar para '0 */1 * * *' (1 hora), '0 */12 * * *' (12 horas) ou qualquer outra frequência que precisar. Veja crontab.guru para ajuda com sintaxe cron.

Meus dados estão seguros neste sistema?

Sim. Credenciais são armazenadas como secrets criptografados no GitHub, nunca no código. A API REST roda localmente em localhost. O .gitignore bloqueia arquivos sensíveis. O repositório público contém apenas placeholders. Seus dados no Google Drive permanecem sob seu controle. Aqui no @CanalQb, seguimos as melhores práticas de segurança.
